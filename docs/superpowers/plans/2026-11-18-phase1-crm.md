# QeydAI Phase 1 CRM — Multi-tenant Sales Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace single-tenant lead register with per-business sales workspaces, roles, Contacts, Deals, Conversations, Kanban, custom fields, tasks, notes, phone matching, unified timeline, and lead migration.

**Architecture:** SQLite + Postgres store parity; /api/panel/* RBAC routes behind HMAC cookie auth; UI panel components extended; i18n AZ/EN keys; unit + E2E tests.

**Tech Stack:** Node 24 node:sqlite, PostgreSQL 15+, Next.js 16 App Router, Tailwind v4, Vitest, Playwright.

**Spec:** docs/superpowers/specs/2026-11-18-phase1-crm-design.md

## Global Constraints

- Node 24 built-in node:sqlite for dev/tests/CI/E2E (ENROLL_DB_FILE).
- PostgreSQL 15+ production (QEYDAI_DATABASE_URL), TIMESTAMPTZ, TEXT+CHECK, JSONB, TEXT[], RLS app.tenant_id.
- HMAC-SHA256 HttpOnly SameSite=Lax cookie (qeydai_panel), sameOrigin CSRF on mutations, readLimitedUtf8, rate limiting, fail-closed QEYDAI_API_KEYS/QEYDAI_ADMIN_KEYS, noStoreHeaders.
- CAVEMAN MODE (full): terse responses; technical terms exact.
- Auth: env keys authenticate directly, fail closed; no sales_member_keys seed in migration; initial owner from QEYDAI_ADMIN_KEYS.
- New workspace: manual DB/ops; no Phase 1 onboarding endpoint.
- Inbound message with no existing thread/deal → new deal in 'new' stage, unassigned; operator claims via /claim.
- Migration: unknown crm_leads.stage values → 'new'; migration must not fail.
- Phone: normalizeAzPhone canonical +994XXXXXXXXX (050/50/+99450 accepted).

## Review Focus

1. Missing RLS fail-closed NULLIF on any sales_* table → cross-tenant leak. Pinned in Task 1 (RLS tests).
2. sales_messages insert placeholder mismatch (6 vs 7) → ingest crash. Pinned in Task 2 (insert test).
3. crm_leads.stage value not in default 5 stages → migration FK failure. Pinned in Task 1 (stage map test).
4. Inbound message for contact with no thread/deal → no deal to attach, conversation lost. Pinned in Task 2 (ingestMessage new-deal test).
5. Phone normalization mismatch → matches never created, unconfirmed banner broken. Pinned in Task 2 (normalizeAzPhone edge cases).
6. Operator claim race: two operators claim same unassigned deal → double assignment. Pinned in Task 4 (/claim atomic WHERE assignee_id IS NULL test).
7. Cross-tenant access via guessed deal/contact id → 403 expected. Pinned in Task 4 (cross-tenant route tests).
